# ShellBags Forensics

## 1. What are ShellBags?

ShellBags are Windows forensic artifacts created by Windows Explorer.

Windows uses ShellBags to remember how a user viewed folders. For example,
Windows can remember:

- Window size
- Icon layout
- Column settings
- Sort order
- Folder view type

So, if a user changes a folder to **Details View**, Windows can remember
that setting the next time the folder is opened. :contentReference[oaicite:1]{index=1}

From a forensic point of view, ShellBags are much more interesting because
they can also show evidence of **folders that a user previously browsed**.

---

## 2. Why are ShellBags Important?

ShellBags can help investigators understand a user's navigation activity
in Windows Explorer.

One important thing I learned is that ShellBags may contain evidence of a
folder even after that folder is no longer available.

For example:

- A folder may have been deleted.
- A USB drive may have been disconnected.
- A network share may no longer exist.
- A staging directory may have been removed.

The ShellBag entry may still provide evidence that the user accessed that
location in the past. :contentReference[oaicite:2]{index=2}

This makes ShellBags useful in investigations involving:

- Insider threats
- Data theft
- USB usage
- Removable media
- Malware activity
- Deleted folders
- Network shares
- User activity reconstruction

---

## 3. Where are ShellBags Stored?

ShellBag information is stored in the Windows Registry.

Important Registry locations include:

```text
HKEY_CURRENT_USER\Software\Microsoft\Windows\Shell\Bags

HKEY_CURRENT_USER\Software\Microsoft\Windows\Shell\BagMRU
```

Additional ShellBag information can be found in the user's:

```text
UsrClass.dat
```

Because ShellBags are user-specific, investigators commonly analyze:

```text
NTUSER.DAT
UsrClass.dat
```

These Registry hives contain information associated with the user's
activity. :contentReference[oaicite:3]{index=3}

---

## 4. What Information Can ShellBags Contain?

ShellBags can contain information such as:

- Folder names
- Folder paths
- Folder hierarchy
- View settings
- Window size and layout
- Last interaction timestamps
- Removable drive paths
- Network share locations

This information can help reconstruct how a user navigated through the
file system. :contentReference[oaicite:4]{index=4}

---

# 5. ShellBags and Deleted or Disconnected Locations

One of the most useful things about ShellBags is that they can preserve
historical information.

For example:

```text
USB Drive
    ↓
User opens a folder
    ↓
ShellBag information is created
    ↓
USB drive is disconnected
    ↓
ShellBag evidence may still remain
```

The same concept can apply to:

- Deleted folders
- Network shares
- Removed user profiles
- Malware staging directories

Therefore, finding a ShellBag entry does not necessarily mean that the
folder currently exists. It can represent previous user activity. :contentReference[oaicite:5]{index=5}

# 6. Tools Used for ShellBag Analysis

## RegRipper

RegRipper can parse Windows Registry hives and extract forensic artifacts.

If the Registry hive has already been processed using RegRipper, the output
can be opened in **Notepad++**.

I can search the output for:

```text
shellbags
```

This makes it easier to locate the ShellBag information in the generated
report. :contentReference[oaicite:6]{index=6}

---

## Notepad++

Notepad++ can be used to examine the text output generated by RegRipper.

For ShellBag analysis, searching for:

```text
shellbags
```

can quickly locate the relevant extracted information.

---

## ShellBagsExplorer

ShellBagsExplorer is a forensic tool developed by **Eric Zimmerman**.

It provides a graphical interface for viewing ShellBag information.

It makes it easier to examine:

- Folder structures
- Folder paths
- Timestamps
- User navigation activity

This is much easier than manually analyzing raw Registry data. :contentReference[oaicite:7]{index=7}

---

# 7. Using ShellBagsExplorer

The basic workflow I learned is:

### Step 1: Open ShellBagsExplorer

Launch the ShellBagsExplorer executable from the Zimmerman tools
directory.

### Step 2: Load an Offline Registry Hive

Go to:

```text
File → Load Offline Hive
```

### Step 3: Select the Hive

Navigate to the location where the collected Registry hives are stored.

Load:

```text
UsrClass.dat
```

for the user account being investigated.

### Step 4: Analyze the Results

After loading the hive, ShellBagsExplorer displays the information in a
tree-like structure.

This allows the investigator to examine:

- Folder paths
- Folder hierarchy
- Timestamps
- User interaction

It can also show folders that may no longer exist on the system. :contentReference[oaicite:8]{index=8}

# 8. Example of Forensic Use

Suppose a user says:

> "I never accessed that confidential folder."

Investigators can examine ShellBag artifacts to determine whether Windows
Explorer previously browsed to that folder.

For example:

```text
External Drive
└── Confidential
    └── Project_Data
```

If ShellBag evidence shows that the folder was previously browsed, it can
provide useful evidence of user interaction.

However, this does **not automatically prove that files were opened,
copied, or stolen**.

Other forensic evidence should be examined to understand what actually
happened. :contentReference[oaicite:9]{index=9}

---

# 9. ShellBags in Malware Investigations

ShellBags can also help during malware investigations.

For example, an attacker may create a temporary directory to store:

- Malware
- Attack tools
- Stolen information
- Files waiting to be exfiltrated

If the directory is later deleted, ShellBag information may still provide
evidence that the user or attacker browsed to that location. :contentReference[oaicite:10]{index=10}

---

# 10. Limitations

ShellBags are useful, but they should **not be treated as standalone
evidence**.

Important limitations include:

- Old ShellBag entries may eventually be overwritten.
- Cleanup utilities may partially remove ShellBag data.
- Timestamps must be interpreted carefully.
- ShellBags mainly track interaction through Windows Explorer.
- Command-line activity may not create the same ShellBag artifacts.

Therefore, ShellBag findings should always be correlated with other
forensic artifacts. :contentReference[oaicite:11]{index=11}

---

# 11. Correlating ShellBags With Other Artifacts

To build a stronger investigation, ShellBag evidence can be compared with:

- RecentDocs
- LNK shortcut files
- Jump Lists
- USB artifacts
- UserAssist
- Registry MRU entries
- Prefetch
- Windows Event Logs
- File-system timestamps

No single forensic artifact tells the complete story.

The best approach is to combine multiple artifacts and use them together
to reconstruct user activity and build an investigation timeline. :contentReference[oaicite:12]{index=12}
