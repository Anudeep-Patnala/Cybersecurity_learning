# Windows Artifacts: Windows Event Logs and Sysmon

## Overview

Windows Event Logs and Sysmon are two of the most important sources of evidence in Windows forensic investigations and incident response.

These logging systems provide investigators with detailed information about what happened on a Windows system, including:

- User logons
- Process execution
- Service creation
- PowerShell activity
- Network connections
- Registry modifications
- DNS queries
- File creation
- Other system activity

Windows generates thousands of events every day related to:

- User activity
- Security operations
- Applications
- Services
- Drivers
- System behavior

From a forensic perspective, these logs help investigators:

- Reconstruct timelines
- Identify attacker activity
- Validate suspicious behavior
- Understand how a compromise unfolded
- Identify persistence mechanisms
- Detect malware execution
- Trace attacker activity
- Discover Indicators of Compromise (IOCs)

---

# 1. Windows Event Logs

Windows Event Logs are one of the most powerful logging capabilities built into Windows.

The logs contain information about different activities occurring on the system.

Windows Event Logs are normally stored in:

```text
C:\Windows\System32\winevt\Logs
```

The logs use the:

```text
.evtx
```

file extension.

Examples of Event Log providers include:

- Security
- System
- PowerShell
- Windows Defender
- Sysmon
- Applications

---

# 2. Windows Event Viewer

Windows Event Viewer is the built-in Windows tool used to view Event Logs.

However, Event Viewer does not simply display the raw `.evtx` data.

It combines:

```text
.evtx log data
+
Event mappings
↓
Human-readable event information
```

Because different tools may parse and interpret these mappings differently, the same event can sometimes appear differently depending on the tool being used.

# 8. Windows Defender Logs

One of the first things investigators should check is whether security tools were disabled.

The important Windows Defender Event IDs are:

```text
5000 → Defender Enabled
5001 → Defender Disabled
```

By filtering Defender logs for Event IDs:

```text
5000
5001
```

we can determine whether Windows Defender was enabled or disabled during the incident.

---

## Event ID 5001 — Defender Disabled

If Event ID `5001` appears before suspicious activity begins, this can be an important finding.

In the investigation, Windows Defender was disabled before the attack activity began.

This is suspicious because attackers frequently disable antivirus software before:

- Deploying malware
- Executing malicious scripts
- Performing malicious activity

# 9. System Logs and Services

Windows System Logs can be used to investigate service creation.

The important Event ID is:

```text
7045
```

## Event ID 7045

Event ID 7045 records the installation of a new Windows service.

Services are important from a forensic perspective because attackers can abuse them for persistence.

A malicious service can automatically start whenever the system boots.

# 12. Linked Logon ID

One particularly useful investigative technique is pivoting on the:

```text
Linked Logon ID
```

The Linked Logon ID allows investigators to correlate multiple activities performed within the same authenticated session.

The idea is:

```text
Successful Login
       ↓
Logon ID
       ↓
Search for the same Logon ID
       ↓
Find related activity
       ↓
Understand what the user did
```

In the example, filtering for:

```text
0xD50A4
```

revealed multiple suspicious processes, including activity related to creating a new user account. :contentReference[oaicite:7]{index=7}

# 14. PowerShell Logging

PowerShell logging is one of the most valuable sources of evidence during modern Windows investigations.

Attackers heavily abuse PowerShell because it is:

- Built into Windows
- Highly flexible
- Capable of executing scripts
- Capable of executing commands directly in memory

PowerShell can therefore be used for:

- Malware execution
- File downloads
- Persistence
- Process injection
- File deletion
- Other malicious activity

---

Standard Windows logs are extremely valuable, but they may not always provide enough detail for advanced threat hunting and incident response.


Investigators combine:

- Defender Logs
- System Logs

# 43. Key Takeaways

- Windows Event Logs are a major source of forensic evidence.
- Windows generates thousands of events related to system and user activity.
- Event Logs are stored as `.evtx` files.
- The default Event Log location is:

```text
C:\Windows\System32\winevt\Logs
```

- Event Viewer combines raw `.evtx` information with event mappings.
- Different tools may display events differently.
- EvtxECmd can parse Event Logs into CSV format.
- Timeline Explorer can be used to search and filter the resulting CSV.
- Event Log Explorer can be used to inspect raw `.evtx` files.
- Defender Event ID 5001 can indicate that Defender was disabled.
- Event ID 7045 can identify newly installed services.
- Event ID 4624 can identify successful logons.
- Event ID 4720 can identify newly created accounts.
- PowerShell logging can reveal malicious commands and scripts.
- Event ID 4104 is useful for investigating PowerShell Script Block activity.
- `Invoke-WebRequest` can reveal suspicious file downloads.
- Base64-encoded PowerShell can be decoded using CyberChef.
- PowerShell activity can reveal persistence, process injection, DLL injection, and file deletion.
- Sysmon provides detailed visibility into Windows activity.
- Sysmon Event ID 1 records process creation.
- Sysmon provides Process GUID and Parent Process GUID information.
- Parent Process GUIDs can be used to reconstruct process relationships.
- Sysmon Event ID 3 records outbound network connections.
- Sysmon Event ID 11 records file creation.
- Sysmon Event IDs 12 and 13 record Registry activity.
- Sysmon Event ID 22 records DNS queries.
- DNS activity can be correlated with network connections.
- Registry activity can reveal persistence mechanisms.
- Event Logs and Sysmon are much more powerful when correlated together.
- No single artifact should be treated as the complete story.
- Multiple forensic artifacts should be combined to reconstruct attacker behavior.
